# Dev-окружение

Поднимается за ~10 минут, ставить локально не нужно ничего кроме Node и pnpm.

## Почему без Docker

Исходная формулировка T-002 предполагала `docker compose` с PostgreSQL, Redis, MinIO и mailpit.
На Phase 0 принято решение локальный Docker не использовать: инфраструктура — managed cloud.

Практический выигрыш: разработчику нечего устанавливать и нечему ломаться, а Redis —
настоящий, поэтому Lua-скрипты, миллисекундные TTL и pub/sub ведут себя ровно так же,
как в проде. Это критично: на них стоит всё ядро аукциона (T-023, T-024, T-027).

**Dockerfile'ы в репозитории есть и поддерживаются** — образы собирает CI (T-003) и
разворачивает Kubernetes (T-009). Требование ТЗ §1.1 к Docker/K8s в проде не нарушается,
Docker просто не нужен на машине разработчика.

## 1. Требования

|         | Версия | Проверить |
| ------- | ------ | --------- |
| Node.js | ≥ 22   | `node -v` |
| pnpm    | ≥ 11   | `pnpm -v` |

Если pnpm нет: `npm i -g pnpm` (ставится в профиль пользователя, права администратора не нужны).

## 2. PostgreSQL — локальный PG 17

**Решение проекта: для dev используем локальный PostgreSQL 17, managed-Postgres не заводим.**
Neon для разработки избыточен, а локальный инстанс уже стоит на машине.

Параметры:

|                | Значение                                        |
| -------------- | ----------------------------------------------- |
| Порт           | `5433`                                          |
| База           | `auction`                                       |
| Пользователь   | `postgres`                                      |
| Аутентификация | `trust` для `127.0.0.1` — пароль не нужен       |
| Data directory | `C:\Users\koish\AppData\Local\edustream\pgdata` |

```
DATABASE_URL=postgresql://postgres@127.0.0.1:5433/auction
DIRECT_URL=postgresql://postgres@127.0.0.1:5433/auction
```

Если базы `auction` ещё нет:

```bash
"/c/Program Files/PostgreSQL/17/bin/psql.exe" -h 127.0.0.1 -p 5433 -U postgres \
  -d postgres -c "CREATE DATABASE auction"
```

### TLS на localhost выключен сознательно

`pnpm check:env` не считает это ошибкой и для локального адреса печатает
`localhost — шифрование не требуется`. Основание: трафик не покидает машину,
а инстанс работает по `trust`, так что шифровать нечего и не от кого.

**Для любого удалённого хоста отсутствие TLS остаётся ошибкой** и роняет проверку:
в этом трафике ходят ПДн (ФИО, ИИН, телефоны) и деньги. Логика в
[check-env.ts](../apps/api/src/scripts/check-env.ts) различает адреса по хосту,
а не по флагу «выключить проверку», — послабление не может случайно уехать в прод.

### Две строки при одной базе

`DATABASE_URL` и `DIRECT_URL` локально совпадают: пулера нет, разделять нечего.
Разойдутся они на stage и в проде, где приложение ходит через пулер, а Prisma
выполняет миграции напрямую — DDL и advisory-локи через PgBouncer в
transaction-режиме не работают. Переменные заведены сразу, чтобы конфиг
не переписывать при выкате.

### Чем платим

Инстанс на 5433 принадлежит **другому проекту** (EduStream) — база `auction` живёт
рядом с его базой в одном кластере. Практические следствия: если его окружение
остановят или снесут, dev-база аукциона уедет вместе с ним, и версия PostgreSQL
общая. Для dev приемлемо; для CI (T-003) и stage (T-009) базы будут свои.

## 3. Redis — Redis Cloud

1. Регистрация на [redis.io/try-free](https://redis.io/try-free), план **Essentials 30 MB (free)**.
2. Регион — ближайший к РК, например `eu-central-1` (Франкфурт).
3. После создания базы: **Connect** → **Redis CLI / connection string** вида
   `redis://default:PASSWORD@HOST:PORT`.
4. В `.env` записать его как **`rediss://`** (две `s`) — TLS обязателен.

Проверь в консоли Redis Cloud, что включён **TLS**. Free tier поддерживает всё, что нам
нужно: `EVAL` (Lua), миллисекундные TTL, pub/sub — `pnpm check:env` это подтвердит.

## 4. Локальная настройка

```bash
pnpm install
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
# вставить DATABASE_URL, DIRECT_URL, REDIS_URL
pnpm check:env
pnpm dev
```

`.env` в `.gitignore` — в репозиторий он не попадёт. Ключи и пароли не коммитим никогда.

### Порты и адреса

| Что                    | Адрес                                                           |
| ---------------------- | --------------------------------------------------------------- |
| API                    | `http://127.0.0.1:3100`                                         |
| Liveness               | `GET /health` — 200, пока жив процесс                           |
| Readiness              | `GET /health/ready` — 200 / 503 по состоянию PostgreSQL и Redis |
| OpenAPI (Swagger UI)   | `http://127.0.0.1:3100/docs`                                    |
| OpenAPI (JSON)         | `http://127.0.0.1:3100/docs-json`                               |
| Web (появится в T-006) | `http://127.0.0.1:3101`                                         |

Порты 3100/3101, а не привычные 3000/3001: на dev-машине 3000 уже занят другим
проектом, причём только на IPv6 (`::1`). Из-за этого `localhost:3000` открывал бы
чужое приложение, а `127.0.0.1:3000` — наше; отлаживать такое врагу не пожелаешь.

### Liveness и readiness — почему это две разные ручки

`/health` намеренно не трогает БД. Если завязать liveness на PostgreSQL, то падение
базы заставит Kubernetes перезапускать совершенно исправные поды — во время торгов
это добьёт систему вместо починки. Readiness же зависимости проверяет и отдаёт 503:
балансировщик перестаёт слать трафик, но под остаётся жив и переживает сбой БД.

## 5. Что проверяет `pnpm check:env`

Не «пинг ради пинга», а именно те возможности, без которых не поедет ядро аукциона:

| Проверка                                        | Зачем                                                                |
| ----------------------------------------------- | -------------------------------------------------------------------- |
| Postgres: соединение + версия ≥16               | базовая работоспособность                                            |
| Postgres: TLS                                   | обязателен для удалённых хостов; на localhost осознанно пропускается |
| Postgres: права `CREATE`/`DROP` по `DIRECT_URL` | миграции T-007                                                       |
| Redis: версия ≥7, TLS                           | базовая работоспособность                                            |
| Redis: `EVAL` (Lua)                             | атомарное ядро ставки, T-024 — managed-тарифы иногда режут EVAL      |
| Redis: `PTTL` в миллисекундах                   | таймер 50 000 мс, FR-01                                              |
| Redis: pub/sub round-trip                       | stateless WS-gateway за балансировщиком, T-023                       |

Скрипт возвращает ненулевой код, если хоть одна проверка провалилась, — его можно
поставить в CI и в пре-флайт перед `pnpm dev`.
