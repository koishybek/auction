# Периметр Cloudflare (T-050, NFR-05)

**Статус: не применялось.** Аккаунта и зоны у проекта нет, поэтому конфигурация
не прошла ни `terraform plan`, ни `apply`. Ниже — то, что нужно сделать и почему;
проверять придётся на живой зоне.

## Что здесь есть

`main.tf` — настройки зоны, WAF-правила, ограничение частоты, виджет Turnstile.
Кодом, а не кликами в панели: правила периметра защищают деньги, и «кто-то
поменял в UI полгода назад» здесь такой же плохой ответ, как в миграциях БД.

```bash
terraform init
terraform plan -var zone_id=... -var account_id=... -var domain=auction.kz
```

## Половина DoD, которую Cloudflare не закрывает

DoD задачи: «stage работает только через Cloudflare (прямой IP закрыт)».
Настройками Cloudflare это не делается — закрывать нужно на своей стороне:

1. **Ingress принимает только сети Cloudflare.** Списки публикуются на
   `https://www.cloudflare.com/ips/` и меняются; их нужно обновлять, а не
   вписать один раз.

   ```yaml
   # infra/helm/auction/values-stage.yaml
   ingress:
     annotations:
       nginx.ingress.kubernetes.io/whitelist-source-range: '<списки Cloudflare>'
   ```

2. **Origin-сертификат Cloudflare** на ingress и режим `ssl = strict`. Иначе
   участок «периметр → сервер» остаётся открытым, а по нему ходят ИИН и деньги.

3. **`TRUST_CLOUDFLARE_IP=true` включается ТОЛЬКО после пунктов 1–2.**
   Заголовок `CF-Connecting-IP` дописывает кто угодно, кто достучался до origin
   напрямую. Пока origin открыт, включённый флаг означает, что лимит ставок
   (FR-10) и антинакрутка просмотров (FR-15) верят атакующему на слово.
   Зависимость проверяется кодом только частично: флаг по умолчанию выключен,
   но включить его при открытом origin никто не мешает.

## WebSocket

`websockets = "on"` в настройках зоны — без него торгов нет вовсе.

Оговорка про DoD «WS-сессии живут ≥30 мин»: Cloudflare рвёт бездействующие
WebSocket примерно через 100 секунд тишины. У нас тишины не бывает — сервер
шлёт `ping` каждые 2 секунды и тик таймера каждую секунду (ТЗ §2.1–2.2), — но
проверить это можно только на живом контуре. Если окажется, что рвёт, лечится
не настройкой Cloudflare, а тем, что heartbeat уже есть.

## Плейбук «Under Attack»

Режим включается вручную и **не должен** висеть постоянно: он показывает
проверку браузера всем подряд, а во время торгов это потерянные ставки.

1. Признаки: всплеск 5xx на origin, рост очереди в gateway, отказы
   `security.bid_amount_tampering` пачками (T-048).
2. `security_level = "under_attack"` в панели или переменной.
3. Проверить, что WebSocket живут: режим не должен рвать зал.
4. Выключить сразу после спада — не «завтра посмотрим».

Отдельно: **включение режима во время идущих торгов ломает участникам вход в
зал**. Если атака пришлась на активный лот, решение о включении — человека, и
принимать его нужно, понимая, что часть участников не успеет поставить.
